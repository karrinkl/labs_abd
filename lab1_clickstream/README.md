# Лабораторная работа № 1 — вариант № 2

**Тема:** «Выбор и обоснование архитектуры системы хранения и обработки данных для бизнес-задачи».
**Вариант № 2:** система обработки clickstream-данных для оптимизации воронки продаж (100–300 млн событий в месяц; источники — JSON-логи сайта, системы веб-трекинга, A/B-тесты, CRM).
**Итог:** архитектура Data Lakehouse с потоковым приёмом: Kafka → Spark Structured Streaming → Apache Iceberg (Bronze/Silver/Gold) в S3-совместимом хранилище → Trino / API метрик / Superset.

> Работа выполнена на уровне архитектурного проектирования. Система не реализовывалась и не тестировалась, все числовые примеры условные.

## Что нужно заполнить или проверить самостоятельно

1. **Титульный лист** — все поля в квадратных скобках: учебное заведение, факультет, кафедра, дисциплина, номер группы, ФИО студента, должность и ФИО преподавателя, город, год.
2. **Методичка в списке источников** (п. 1 в разделе 14 отчёта и в `sources.md`) — выходные данные: автор(ы), учебное заведение, год.
3. **Требования кафедры к оформлению** (шрифт, поля, оформление подписей и списка литературы). Если они отличаются, поправьте `tools/make_reference.py` или стили прямо в Word / LibreOffice.
4. **Содержание.** В `report.docx` оно уже заполнено с номерами страниц, рассчитанными по вёрстке LibreOffice. В Word разбивка на страницы может немного отличаться — обновите поле: правой кнопкой по содержанию → «Обновить поле» → «Обновить целиком» (или `F9`). В LibreOffice: «Сервис → Обновить → Обновить все».
5. **Даты обращения к источникам** (19.10.2026) — при необходимости замените датой сдачи работы и проверьте ссылки.

Быстрая правка титульного листа: откройте `report.docx` в LibreOffice Writer или Word, нажмите `Ctrl+H` и ищите `[` — так найдутся все поля для замены.

## Просмотр без установки программ

- **Отчёт:** `report.docx` открывается в LibreOffice, Word, Google Docs или «Яндекс Документах»; `report.md` читается в любом текстовом редакторе и на GitHub.
- **Диаграммы:** файлы `*.svg` открываются в любом браузере (`firefox c4_container.svg`) с масштабированием без потери качества.
- **Правка диаграмм онлайн:** скопируйте содержимое `.puml` в веб-редактор https://www.plantuml.com/plantuml/uml/ — строка `!include <C4/C4_Context>` поддерживается сервером, и изображение появится сразу. В диаграммах только условные названия систем, поэтому их можно отправлять на внешний сервер; конфиденциальные данные туда не вставляйте.
- **VS Code / VSCodium:** расширение *PlantUML* (jebbs.plantuml) показывает предпросмотр по `Alt+D`.

## Установка инструментов в Arch Linux

```bash
sudo pacman -S --needed plantuml graphviz jre-openjdk \
                        pandoc-cli python-docx \
                        libreoffice-fresh poppler \
                        ttf-dejavu ttf-liberation
```

- `plantuml`, `graphviz`, `jre-openjdk` — рендеринг диаграмм (стандартная библиотека C4-PlantUML встроена в PlantUML, сеть не нужна);
- `pandoc-cli` — конвертация Markdown → DOCX (в Arch пакет pandoc называется `pandoc-cli`);
- `python-docx` — постобработка DOCX;
- `libreoffice-fresh` (или `libreoffice-still`) и `poppler` (`pdftotext`) — номера страниц в содержании и экспорт в PDF;
- `ttf-dejavu` — шрифт диаграмм; `ttf-liberation` — Liberation Serif, которым LibreOffice заменяет Times New Roman без изменения разметки страниц. Если нужен именно Times New Roman, установите пакет `ttf-ms-fonts` из AUR (например, `yay -S ttf-ms-fonts`).

Проверка: `plantuml -version`, `pandoc --version`, `python -c "import docx"`.

## Пересборка

Всё сразу (диаграммы + отчёт):

```bash
cd lab1_clickstream
./build.sh
```

Если PlantUML скачан вручную как jar-файл:

```bash
PLANTUML="java -jar ~/Downloads/plantuml.jar" ./build.sh
```

Только диаграммы:

```bash
plantuml -checkonly c4_context.puml c4_container.puml   # проверка синтаксиса
plantuml -tsvg c4_context.puml c4_container.puml         # SVG
plantuml -tpng -Sdpi=180 c4_context.puml c4_container.puml  # PNG для отчёта
```

Только отчёт (без пересчёта номеров страниц в содержании):

```bash
pandoc report.md -t docx --reference-doc=tools/reference.docx \
       --highlight-style=monochrome -o report.docx
python tools/postprocess_docx.py report.docx
```

Экспорт в PDF (если преподаватель просит PDF):

```bash
libreoffice --headless --convert-to pdf report.docx
```

## Как редактировать

**Вариант А — в Markdown (рекомендуется для крупных изменений).** Правьте `report.md` и запускайте `./build.sh`. Особенности разметки:

- блоки `::: {custom-style="Title Page ..."}` — титульный лист (стили заданы в `tools/reference.docx`);
- строка `Таблица N — ...` перед таблицей — подпись таблицы (постобработка оформляет её как подпись);
- `![Рисунок N — ...](файл.png){width=100%}` — рисунок с подписью;
- `$...$` и `$$...$$` — формулы в синтаксисе LaTeX (в DOCX превращаются в редактируемые формулы Word);
- ширина столбцов таблицы задаётся количеством дефисов в строке-разделителе `|----|--------|`.

**Вариант Б — сразу в DOCX.** Откройте `report.docx` в LibreOffice Writer или Word и правьте как обычный документ. Учтите, что следующий запуск `./build.sh` перезапишет DOCX из `report.md`, поэтому выберите один способ.

**Диаграммы.** Правьте `.puml` и перерисуйте их (см. «Пересборка»). Названия элементов в диаграммах совпадают с названиями в разделах 6–11 отчёта; при переименовании компонента меняйте его в обоих местах. Основные макросы: `Person(...)`, `System(...)`, `System_Ext(...)`, `Container(...)`, `ContainerDb(...)`, `ContainerQueue(...)`, `Rel(от, к, "что передаётся", "протокол")`; `Rel_U/Rel_D/Rel_L/Rel_R` и `Lay_*` управляют взаимным расположением элементов.
